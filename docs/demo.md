# 演示与本人验收手册

## 面试前彩排准备

1. 提前在实际演示电脑安装Python依赖，确认项目解释器正确；日常演示使用仓库自带前端构建文件。
2. 停止旧的StoreFlow实例，避免8765端口占用；如改用 `--port 8766`，浏览器也使用对应地址。
3. 在面试前完成一次从启动到归还的彩排，并验证依赖安装后断网仍可操作。
4. 演示时新建一张申请，预计归还日期选择未来日期；旧的预置样例可能已经到期，过期的待发放申请会按业务规则拒绝发放。
5. 准备好账号表和本手册。若PyCharm本身不能启动，先检查IDE故障；可用该项目虚拟环境在终端运行 `python main.py` 验证Python入口，但不要把终端运行表述为已完成IDE内操作验收。

可预览[登录页](images/login.png)、[角色工作台](images/workbench.png)及[已归还申请的完整时间线](images/loan-complete.png)。截图记录技术演示结果，不替代本次现场操作。

## 五分钟演示

开场：说明这是基于开源 OA 的工程改造，场景是虚构零售门店设备借用，关注申请、设备去向和交接责任。

| 顺序 | 账号 | 操作与观察 |
|---|---|---|
| 1 | employee_a | 创建未来归还日期的申请并提交，展示当前步骤 |
| 2 | manager_a | 在待办中通过本门店申请 |
| 3 | custodian | 选择匹配的空闲设备发放，核对设备编号 |
| 4 | employee_a | 签收后申请归还 |
| 5 | custodian | 正常验收，核对空闲状态、时间线、统计 |

退出登录切换角色，或使用独立浏览器会话。同一登录态下的多个标签不算不同用户。

再展示损坏归还：设备进入待维修，管理员确认修复后才允许再发放。补充一次驳回或跨店权限限制，说明业务异常如何处理。

## 需要能解释的问题

1. 为什么审批通过与设备发放分开？
2. 如何防止同一台设备被两次分配？
3. 前端隐藏按钮后，后端为什么仍要验证权限？
4. 员工点击归还后，设备为什么还不能立即发放？
5. SQLite 和 PostgreSQL 的测试分别证明什么？
6. 如何从状态、网络请求与日志定位故障？

## 本人验收清单

以下由实际使用者操作并记日期，不能预先勾选：

- [ ] 在下载的项目中用 PyCharm 配置解释器并运行 main.py。
- [ ] 依赖已安装后，断网仍可打开页面并完成操作。
- [ ] 不修改数据库，完成申请至正常归还。
- [ ] 完成一次驳回和一次损坏归还。
- [ ] 验证另一门店店长不能操作本申请。
- [ ] 核对当前角色能看到和导出的记录范围。
- [ ] 停止重启后刚创建的记录仍存在。
- [ ] 备份并恢复到新文件，检查记录。
- [ ] 能独立解释角色、状态、资源占用设计。

失败时记录账号、申请编号、时间、现象和请求结果；修复后重走场景。自动化报告不能替代本人操作确认。
