# StoreFlow 业务与实现说明

## 场景与权限

总部设备池为两家虚构门店提供临时借用。一张申请对应一种类别的一台设备，不涉及采购、计费、真实硬件或通用流程设计。员工查看和处理本人申请；店长处理本店；设备管理员管理设备与交接；系统管理员管理配置与账号。店长不兼任员工申请角色。

## 状态规则

申请状态：`draft` 草稿 → `pending` 待审批 → `approved` 待发放 → `handover` 待签收 → `borrowed` 借用中 → `return_pending` 待验收 → `returned` 已归还。分支为 `rejected` 已驳回与 `withdrawn` 已撤回。

设备状态：`available` 空闲、`handover` 交接中、`in_use` 借用中、`inspection` 待验收、`maintenance` 待维修。

| 动作 | 执行者 | 条件与结果 |
|---|---|---|
| 保存、编辑、提交草稿 | 申请员工 | 类别、用途和日期均在后端校验 |
| 通过或驳回 | 本店店长 | 只处理待审批申请；驳回填写说明 |
| 撤回 | 申请员工 | 仅发放前，原记录保留 |
| 发放 | 设备管理员 | 类别匹配、设备空闲、借期未过，原子占用 |
| 撤销发放 | 设备管理员 | 仅未签收时，退回待发放并释放设备 |
| 签收 | 申请员工 | 确认实际设备后进入借用中 |
| 申请归还 | 申请员工 | 设备进入待验收，不提前恢复空闲 |
| 归还验收 | 设备管理员 | 正常恢复空闲；损坏转待维修，本次借用结束 |
| 确认修复 | 设备管理员 | 待维修设备填写说明后恢复空闲 |

日期按 Asia/Shanghai 自然日。预计归还日期已过且处于借用中或待验收时标记逾期，不阻止归还；过期的待发放申请禁止发放，应撤回重新申请。普通编辑接口不能改变关键状态、申请人或审批人。

## 数据与接口

核心数据为门店、设备类别、设备、借用申请和流转记录。设备编号唯一，申请关联申请人、门店、类别、用途、日期、实际设备及处理时间。流转记录追加保存操作者、动作、前后状态、原因和时间。

API：`/api/auth/login/`、`/api/auth/me/`；`/api/categories/`、`/api/stores/`、`/api/assets/`、`/api/requests/`；`/api/dashboard/`、`/api/requests/export/`；`/api/audit/`、`/api/accounts/`；`/api/health/`。

每个动作重新校验角色、归属、门店和状态，列表、详情、导出、统计共享数据范围。发放使用事务与资源条件检查；并发冲突返回可解释的信息，不得重复分配设备。

本机默认 SQLite，PostgreSQL 通过 `DATABASE_URL` 配置。并发测试结果分别注明数据库，不把一种后端的结果代替另一种。界面显示角色待办、当前步骤、责任人与时间线。统计使用后端真实记录，前端构建文件随仓库交付。
